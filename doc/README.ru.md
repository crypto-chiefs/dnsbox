# DNSBox — собственный DNS-сервер и HTTPS для адресных имён

[English](../README.md) · [Развёртывание и приватные сети](deployment.md) · [Настройки](configuration.md) · [Переход с v0.4](migration-v0.5.md)

DNSBox объединяет авторитетный DNS-сервер и обратный HTTPS-прокси. Имя `192-168-1-50.home.arpa` задаёт IP приложения. DNS возвращает **адрес DNSBox**, а DNSBox принимает TLS-соединение и пересылает HTTP-запрос приложению. Поддерживаются IPv4, IPv6 и WebSocket.

Доступны два режима:

- `acme`: публично доверенные сертификаты для имён в **вашем домене**, проверка через ACME DNS-01. Авторитетный DNS должен быть доступен из Интернета.
- `local`: автономный центр сертификации для приватной сети. Интернет, публичный домен и проброс портов не нужны. Корневой сертификат необходимо добавить в доверенные на клиентских устройствах.

Сертификат выдаётся на DNS-имя, а не на голый IP. Установка DNSBox не даёт права управлять чужим доменом `dnsbox.io` и не подтверждает доступность публичного сервиса.

## Пример для локальной сети

Пусть DNSBox работает на `192.168.1.2`, а приложение — на `192.168.1.50:80`.

Скачайте [релиз](https://github.com/crypto-chiefs/dnsbox/releases), проверьте SHA-256 по `checksums.txt` и запустите:

```bash
./dnsboxd --domain=home.arpa --ip=192.168.1.2 \
  --tls-mode=local --allowed-cidrs=192.168.1.0/24 \
  --dns-listen=192.168.1.2:53 --https-listen=192.168.1.2:443 \
  --data-dir=/var/lib/dnsbox
```

Процессу нужны права на каталог данных и указанные порты. На локальном резолвере настройте пересылку запросов **зоны `home.arpa`** к DNSBox. DNSBox не является рекурсивным резолвером для всего Интернета.

При первом выпуске сертификата появятся `/var/lib/dnsbox/ca/root.crt` и приватный ключ центра сертификации. Передайте клиентам только `root.crt` по доверенному каналу и установите его в хранилище доверенных корневых сертификатов. Для отдельной проверки:

```bash
curl --cacert root.crt \
  --resolve 192-168-1-50.home.arpa:443:192.168.1.2 \
  https://192-168-1-50.home.arpa/
```

Предварительно создать CA и сертификат можно запуском с теми же настройками и `--issue=192-168-1-50.home.arpa`. В локальном режиме команда сохраняет сертификат и завершает работу без открытия сетевых портов. Одновременно другой экземпляр не должен использовать тот же каталог данных.

Непустой `--allowed-cidrs` разрешает **только указанные сети**. Без него доступны только публичные адреса приложений. Для приватной установки оставляйте DNS и HTTPS доступными только нужным клиентам в LAN/VPN.

## Установка и запуск без systemd

В [релизе v0.5.2](https://github.com/crypto-chiefs/dnsbox/releases/tag/v0.5.2) есть архивы для Linux, macOS и Windows, amd64 и arm64. Скрипт `scripts/install.sh` проверяет контрольную сумму архива, устанавливает программу в `~/.dnsbox`, а для новой установки выбирает каталог данных `~/.dnsbox/data`.

Установка на Linux и macOS:

```bash
curl --fail --location \
  https://raw.githubusercontent.com/crypto-chiefs/dnsbox/v0.5.2/scripts/install.sh \
  -o install-dnsbox.sh
# Прочитайте скрипт перед запуском.
bash install-dnsbox.sh \
  --domain=home.arpa --ip=192.168.1.2 \
  --tls-mode=local --allowed-cidrs=192.168.1.0/24 \
  --dns-listen=192.168.1.2:53 --https-listen=192.168.1.2:443
```

На Linux скрипт создаёт службу только при работающем systemd. Для Calculate Linux/OpenRC и ручного запуска добавьте `--no-systemd`, затем используйте:

```bash
~/.dnsbox/run-dnsbox
```

Настройки находятся в `~/.dnsbox/dnsbox.env`; повторная установка сохраняет этот файл. Для портов ниже 1024 нужны соответствующие права. Скрипты не меняют системный DNS-резолвер и не удаляют системные журналы.

Для изменения настроек существующей установки отредактируйте `dnsbox.env`. В Windows распакуйте архив и запустите `dnsboxd.exe` с теми же параметрами.

## Let's Encrypt за NAT

Для публично доверенного сертификата делегируйте DNSBox **свой домен или поддомен**. Пробросьте к VM **UDP 53 и TCP 53**, разрешите исходящий HTTPS к ACME-сервису. Для DNS-01 входящий порт 80 не нужен. Порт 443 нужен только тем клиентам, которые подключаются к HTTPS-прокси.

HTTP-приложение при этом может оставаться в приватной сети. Если и сам прокси должен быть доступен лишь внутри сети, отдельно настройте публичный адрес NS и приватный адрес прокси; подробности есть в [руководстве](deployment.md). Полностью изолированная установка использует `local`, а не Let's Encrypt.

```bash
./dnsboxd --domain=apps.example.com --ip=203.0.113.10 --ns=ns1 \
  --acme-email=admin@example.com --data-dir=/var/lib/dnsbox
```

Замените примерные домен и IP своими. `--ip` задаёт адрес DNSBox, доступный клиентам, а не адрес приложения. Если прокси использует IPv4, DNS возвращает A; при IPv6 — AAAA, независимо от семейства адреса приложения.

Открытый API передачи сертификатов больше не существует. Каждый узел хранит собственные сертификаты. Управляющий API по умолчанию слушает только `127.0.0.1:8080`, изменение записей требует токена.

Пустой параметр `--api-listen=` отключает API. Сохраняйте резервную копию каталога данных: в нём находятся сертификаты и приватные ключи.

## Несколько DNS-узлов и ACME

Задайте одинаковый статический список `--nameservers` на каждом узле. Метки должны быть уникальны, адреса — указывать конкретные unicast IP; локальные `--ns` и `--ip` должны совпадать с одной записью. Все узлы публикуют одинаковые NS, адреса соседей и основной сервер SOA. Без этого параметра DNSBox публикует только собственный NS. Делегирование у родительской зоны, glue-записи и пользовательские переопределения адресов NS должны согласовываться.

Для ACME с несколькими авторитетными узлами настройте `--cluster-file` на каждом узле: он включает передачу временных TXT-записей DNS-01. Используйте одинаковую зону, правила доступа к приложениям и пользовательские DNS-записи. Пример для первого узла:

```bash
./dnsboxd --domain=apps.example.com --ip=203.0.113.10 --ns=ns1 \
  --nameservers=ns1=203.0.113.10,ns2=203.0.113.11,ns3=203.0.113.12 \
  --cluster-file=/etc/dnsbox/cluster.json --data-dir=/var/lib/dnsbox
```

Файл `cluster.json` для этого узла:

```json
{
  "listen": "0.0.0.0:8443",
  "certificate": "cluster-node.crt",
  "private_key": "cluster-node.key",
  "ca_certificate": "cluster-ca.crt",
  "peers": ["https://203.0.113.11:8443", "https://203.0.113.12:8443"]
}
```

Каждый узел явно перечисляет все остальные узлы в виде HTTPS URL с IP и портом. Разрешите доступ к порту кластера только этим узлам. Используйте отдельный CA кластера и собственные сертификат и ключ для каждого узла; сертификат должен содержать IP узла в SAN и разрешать аутентификацию сервера и клиента. Пути считаются от каталога JSON-файла. Защитите файлы CA и TLS, а приватный ключ CA храните вне серверов. Узлы проверяют друг друга через mTLS. Передаются только временные TXT-записи: HTTPS-сертификаты, приватные ключи и CA локального режима не передаются. Соответствующие переменные окружения: `DNSBOX_NAMESERVERS` и `DNSBOX_CLUSTER_FILE`.

## ALIAS для корня зоны

Чтобы направить корень зоны на внешнее имя хостинга, добавьте запись в файл, указанный через `--records-file`:

```text
apps.example.com ALIAS landing.example.net.
```

Настройте хостинг на обслуживание вашего домена и HTTPS. DNSBox разрешает целевое имя до готовности DNS, обновляет адреса в фоне и отвечает сохранёнными A/AAAA без сетевого поиска при каждом запросе. Ошибка первого разрешения останавливает запуск; после одного часа без успешного обновления запросы A/AAAA получают SERVFAIL. ALIAS разрешён только в корне зоны, должен указывать за её пределы и не может соседствовать с A, AAAA или CNAME того же имени. NS, SOA, TXT, MX и адресные имена HTTPS-прокси продолжают работать. Статический список NS, обмен TXT и ALIAS требуют версии v0.5.2 или новее.

## Сертификаты для ocserv

Параметр `--issue=имя` позволяет сохранить цепочку `<data-dir>/certs/<имя>.crt` и приватный ключ `<data-dir>/certs/<имя>.key`, не занимая HTTPS-порт. Имя должно принадлежать вашей зоне и содержать разрешённый IP.

Настройте ocserv на эти файлы и направьте DNS-имя непосредственно на сервер ocserv. HTTP-прокси DNSBox не заменяет OpenConnect/DTLS. Для продления нужен повторный запуск до истечения сертификата либо работающий экземпляр DNSBox с последующей перезагрузкой сертификатов в ocserv. См. [подробную инструкцию](deployment.md#certificates-for-ocserv-or-another-service).

## Разработка

Используйте версию Go из [go.mod](../go.mod).

```bash
go test -race ./...
go vet ./...
bash scripts/test-install.sh
go build ./cmd/dnsboxd
```

Перед публикацией релиза выполняются проверки. Архивы собираются для Linux, macOS и Windows на amd64 и arm64.
